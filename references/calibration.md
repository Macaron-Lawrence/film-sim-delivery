## 1. 为什么需要"曝光定位标定"

胶片 LUT 内部把"源白点"放在了某个位置上：

| 来源 | 内部定位 | 直接套上的后果 | 需要的 pre-gain |
|---|---|---|---|
| spektrafilm | 源白点放在 **+4 档**（内部线性增益 2.88） | 整体亮约 1.5 档、发灰发飘 | **0.3472**（=1/2.88） |
| spectral_film_lut 彩色负片 | 中灰落在 140–155 | 略亮 | 0.81–0.83 |
| spectral_film_lut 正片 | 中灰落在 133–140 | 略亮 | 0.85–0.97 |
| spectral_film_lut 黑白 | 中灰落在 99–102 | **偏暗** | 1.47–1.67 |
| RT 集合（295 个卷） | 中灰 111–153 不等 | 有的亮有的暗 | 0.77–1.24 |
| Instax / FP-100C | 中灰 195–208 | **过曝** | 0.46–0.50 |

上表数值属于**未归档的历史报告值，未纳入 CI**（见 §0）：没有该批 LUT 的清单、哈希与完整校准输出。

**结论（这条是结构性的，不依赖上表的具体数字）：pre-gain 是逐卷属性，不能共用。**
`calibrate-luts.py` 的存在本身就说明这一点——不同项目把源白点放在不同位置。
对当前输入请直接跑一次得到真实值，不要套用任何历史范围。

### 怎么算
`calibrate-luts.py` 在**线性域**做乘法后重新编码（`x' = encode(decode(x) · g)`），
用二分求根让目标指标命中：

| 模式 | 目标 | 用在哪 |
|---|---|---|
| `--mode midgray` | 输入中灰 128 → 输出 128 | 影调定位"正确"、保留胶片原本的肩部 |
| `--mode brightness` | 一组中性色阶的加权平均亮度不变 | 观感亮度一致（日常推荐，配合护高光） |

```bash
python3 scripts/calibrate-luts.py --dir <luts> --mode brightness --protect 0.68 \
        --out <luts>/_calibration.json
```

`--protect` 必须与后续生成时一致，否则标定目标和实际交付不是一回事。

## 2. 护高光：把胶片肩部的天花板拆掉

### 问题
胶片印片的肩部会把高光压在一个天花板下（模型里视作白点约 0.82）。下表是一个早期记录的样例，
属**未归档的历史报告值**（见 §0）：

| 输入 | 200 | 220 | 240 | 255 |
|---|---|---|---|---|
| 输出（无护高光） | 192 | 201 | 206 | **209** |

同一批记录还报告：整片最亮 5% 从 248 掉到 208，**≥250 的像素占比 0%**，高光区细节 std 从 6.1 → 1.0。
用户看到的就是"高光被切掉/糊成一片"。**CI 只验证合成 fixture 上纯白明显受压（0–220），不验证上述具体数值。**

### 做法
按**输入亮度**加权混合（生成表格时一次性烘进去）：

```
w(L) = 1                                   L ≤ protect
w(L) = 1 − smoothstep((L−protect)/(1−protect))   protect < L < 1
w(L) = 0                                   L = 1
out  = w · LUT(x) + (1 − w) · x
```

- `protect = 0.68` 是当前默认值（不是唯一正确值；取舍见下表）
- 效果（**按上面的公式与上表重算**，可当场复核）：输入 200/220/240/255 → 输出 194.0/212.5/237.0/**255.0**
  - 早期文档在这一行记的是 198/214/237/255；其中 240 与 255 与重算一致，200 与 220 分别差 4.0 与 1.5，**无法由它自身上一张表复现**（公式见上方伪代码、实现见 `scripts/lut-to-ccprofile.py` 的 `build_table()`）。以代码公式与重算值为准。
- 6 张 RAW 的聚合结果：见 §0 —— **未归档的历史报告值，未纳入 CI**。

### 阈值怎么选

| protect | 高光细节 | 说明 |
|---|---|---|
| 0（不护） | 1.0 | 最"胶片"（肩部被压），但直出观感差 |
| 0.55 | 4.7 | 高光更亮一点 |
| **0.68** | **5.1** | **推荐默认** |
| 0.70 | 5.1 | 与 0.68 接近 |
| 1.0（等于不用 LUT） | — | 无效 |

## 3. 交付前的量化验收

用真实照片（不只是灰阶）测这四个数，缺一不可：

| 指标 | 要求 | 怎么算 |
|---|---|---|
| 平均亮度比 | 0.95 – 1.05 | `out.mean() / src.mean()` |
| 最亮 5% 中位 | ≥ 240 | 取原图亮度前 5% 的像素，看输出亮度的**中位数**（字段名 `top5pct_median`；早期行文误写作"均值"） |
| ≥250 像素占比 | ≥ 2.5% | 输出中亮度 ≥250 的像素占比 |
| 高光区细节 std | ≥ 3.5 | 高光区亮度标准差 |

后两行的参考值（"原图约 4%"、"原图约 6.1，未护高光只有 1.0"）来自 §0 的未归档记录，
当前 CI 不复算；**阈值本身是验收目标，可以照用，参考值不要当基准**。

其它两条结构性检查：
- 生成文件解回后与源 LUT 的最大误差 **≤ 1/65535**（纯取整）
- 表格元数据与基底配置文件**配对正确**（见 `rgb-table-format.md` §3）

```bash
bash scripts/selftest.sh     # 最小闭环：造 LUT → 标定 → 转配置 → 解回 → 护高光断言
```

## 4. 两条常见误区

1. **"用曝光滑块补偿就行"**：在 LR 里加曝光是在**配置文件之前**生效，
   能把中间调抬起来，但高光仍然被肩部压住——治标不治本。护高光才是正解。
2. **"降低 Amount 就能救高光"**：Amount 会把整个看回混（包括已经正确的中间调），
   不如护高光精确。二者可以叠加使用，但先上护高光。
